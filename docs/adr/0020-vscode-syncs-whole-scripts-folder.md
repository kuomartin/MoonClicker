# VS Code 以三方比對同步整個 scripts 資料夾，本機資料夾以裝置的 instance id 對應

VS Code 擴充套件把裝置的整個 `scripts/` 同步到使用者選的一個本機資料夾，每支腳本是其中一個子資料夾，資料夾以單一 workspace folder 開啟。連線時以上次兩邊一致時各檔案的 sha256 為基準（存在本機資料夾的 `.moonclicker/state.json`）做三方比對：只有一邊改過就同步那一邊；兩邊都改過則保留本機版本、裝置版本另存為 `.device` 檔，並把基準記成裝置版本，之後以本機為準；一邊刪除、另一邊有修改則保留修改的版本；本機整支腳本資料夾消失時，刪除裝置上的腳本前先詢問。本機資料夾與裝置的對應以 App 安裝時產生的 instance id（`GET /device`）為鍵，同步狀態也記錄這個 id，另一台裝置不能沿用同一個資料夾。

理由：使用者要能看到並用 git 管理自己的腳本，所以資料夾必須是使用者選的、看得到的位置。斷線期間兩邊都可能改動（手機上用檔案管理員、匯入 zip、加入內建範例），單向覆蓋一定會默默丟掉其中一邊的修改；沒有基準就分不出是哪一邊改的。位址會隨 DHCP 變動，mDNS 名稱只是型號，以它們辨識裝置可能把另一台裝置的腳本當成「被刪除」而刪掉本機檔案。

## Considered Options

- **每支腳本各自鏡像到 globalStorage、各自成為 workspace folder**（先前的做法）：檔案藏在使用者看不到的位置，無法自己管理版本；每加一個 workspace folder 都會讓擴充套件重啟，multi-root workspace 還會詢問是否存檔。
- **連線時只從裝置往本機拉**：實作最簡單，但斷線期間本機的修改會被裝置版本覆蓋。
- **以檔案修改時間判斷新舊**：手機與電腦的時鐘不一定一致，複製、解壓縮也會改變修改時間，判斷結果不可靠。
- **衝突時保留兩邊、直到使用者手動標示解決**：需要額外的「已解決」操作，否則每次同步都卡在同一個衝突；以本機為準加上 `.device` 副本，不需要新操作也不會遺失內容。

## Consequences

- 直接在手機上（App、檔案管理員）做的改動不會推送事件，要等下次連線的完整比對才會同步。
- 清除 App 資料或重裝會產生新的 instance id，使用者需要重新選擇資料夾；選回同一個資料夾時會因為 id 不同被拒絕，要選新的資料夾或刪除其中的 `.moonclicker/`。
- 新腳本的資料夾名稱同時是裝置上的 id，必須符合 `Script.UNIQUE_ID_PATTERN`；不符合的本機資料夾不會同步，並告知原因。
- 本機改名以「刪除舊路徑、推送新路徑」處理，不使用裝置的改名 API；大型資料夾改名會重新上傳。
