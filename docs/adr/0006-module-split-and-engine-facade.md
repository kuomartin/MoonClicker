# Split into :engine/:overlay/:simplescript/:app, with :engine as the sole native-access boundary

The app was a single `:app` module where Overlay UI and `FullscreenDisplayActivity` each reached directly into the JNI bridge (`LuaNative`) and into a global `OverlayServiceProvider` singleton, and where the only visible engine state was a 500ms poll of a single `isEngineRunning()` boolean. We split into `:engine` (owns the RelcEngine/LuaNative JNI bridge and RelcV2Service/Shizuku, the only module allowed to touch native internals — `LuaNative` is `internal`; other modules go through the public `LuaEngineControl` facade), `:overlay` and `:simplescript` (both depend only on `:engine`, never on each other), and `:app` as the composition root that wires them together (e.g. hosting `simplescript`'s nav graph as a bottom sheet from `FullscreenDisplayActivity`). `:engine` exposes a read-only `EngineStateRepository` (a single `StateFlow<EngineState>` aggregating run state and the latest match result — see `docs/adr` history note below on scope), fed by a new single JNI upcall channel `onEngineEvent(eventType, payload)` — replacing the pattern of adding a new per-purpose `jmethodID` upcall for every new bit of state. `OverlayServiceProvider`'s static singleton is replaced with `OverlayController`, a Hilt `@Singleton` the service attaches/detaches itself to.

Legacy `script.simple.*` (JSON-persisted, ~20 files) is intended to eventually be removed in favor of `simplescript.*` (Room-backed), but `simplescript.*` currently has no execution engine — its `ScriptCompiler` emits Lua source that nothing yet feeds to `NativeLuaScriptRunner`. Building that path and migrating/dropping legacy data is deliberately out of scope for this module split; legacy code stays in `:app`, unmoved, until that follow-up work happens.

Moving `ClickAssistOverlayService` into `:overlay` surfaced a coupling this ADR didn't originally anticipate: the service rendered legacy Simple Script editor UI (`overlay/ui/simple/*`) inline, which depends on `script.simple.*` — moving the service wholesale would have made `:overlay` depend back on `:app`. Fixed with `OverlayContentExtension`, a Hilt-multibound interface (`Map<String, OverlayContentExtension>`, keyed by a plain string matching `ScriptConfig.ScriptCodeType.name`) that `:overlay` defines and resolves without knowing `ScriptConfig` exists; `:overlay` registers the Lua-UI renderer, `:app` registers the legacy Simple-Script renderer.

## Scope note

`EngineStateRepository` currently covers run state (idle/starting/running/finished/error/stopped) and the latest match result — not per-virtual-display state, which the original draft of this ADR anticipated. That would require wiring `RelcV2Service`'s display bookkeeping (a separate source of truth) into the same repository, deliberately left as unstarted follow-up work rather than a half-built field.

## Status

Accepted, partly superseded by [ADR-0007](0007-drop-lua-overlay-ui-for-status-notification.md): the `:overlay` module, `OverlayController`, and the `OverlayContentExtension` seam described above no longer exist. The `:engine`/`:simplescript`/`:app` split, `LuaEngineControl`, and `EngineStateRepository` are unaffected.
